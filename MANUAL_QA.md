# Manual browser checks — not yet performed

Browser-control tooling is unavailable in this session. The nine uploaded photographs have been inspected locally and integrated. These steps still need a real browser: file inspection and containment rules do not establish actual layout, contrast, motion or overflow quality.

1. Run `npm ci` then `npm run dev`. Open the printed local URL. In developer tools, test 390×844, 768×1024 and 1440×900. Confirm readable headings, no horizontal scroll and no header overlap. Also check 360px width as an extra small-screen case.
2. Home: the header begins translucent/readable over the hero and turns solid after about 40px of scroll. The headline/supporting copy enters in a brief stagger; both CTAs work immediately.
3. Hero: wait at least 7 seconds for the active slide/indicator to change. Inspect the 1000ms mask/crossfade and subtle scale with the installed photographs. Press Pause and wait 14 seconds: no advance. Press Play: advancement resumes. Select a slide, use previous/next, focus a CTA or touch the hero: automatic advancement stops. Switch to another tab and back: it stays paused until Play is selected.
4. Scroll down naturally. Check image masks, staggered collection entries, text fades and limited desktop parallax on the first collection image and texture interlude. Compare mobile: no parallax. Verify section content remains visible with reduced motion or IntersectionObserver unavailable.
5. “Scroll to discover” must focus/scroll the Collections section. Tab to “Skip to content” and activate: focus reaches main content. Neither action opens a missing route. From Contact, activate Atelier: Home opens and the Atelier section receives focus.
6. Lookbook: activate each category using mouse/touch and keyboard. The visible records and announced count match. Changes should fade/move without an empty flash; confirm no stale card positions/overlap.
7. Open a look with Enter. Focus stays inside the native dialog when tabbing. Check the close button, Escape and an outside click; normal closing animates before focus returns to the trigger. On mobile, close remains visible. One-photo records must not pretend to have alternate views; controls are explicit. Test zoom with the installed photographs. Any later record with verified matching views must support next/previous buttons and arrow keys.
8. Open the mobile menu, tab around it, close it with its button and Escape, then reopen and select Collections/Atelier/Contact. Navigation must release focus containment and scroll locking; the new content should receive focus. Check animated normal menu exits.
9. Contact: select a look reference, enter a message, and Continue on WhatsApp. Inspect the URL/draft without sending it: destination is `2348033895505`, context matches the selected look, stock/illustration references are qualified, approved-brand records are not called stock or illustrations. Whitespace-only text must not open WhatsApp. The site must not say “Message sent.” Check phone/copy and verified Maps links.
10. Emulate `prefers-reduced-motion: reduce`, reload, and wait 14 seconds. The hero stays on its first slide, Play is disabled, manual slides still work, and scrolling/routing/dialogs do not have spatial transitions. Toggle reduced motion while a slideshow is active and verify it stops.
11. Inspect desktop/mobile cropping for every placement. Garments should remain visible, text must remain legible over photography, and stock disclosures remain visible. Block one WebP URL in developer tools and reload: the named fallback appears while navigation/enquiry still work. Pending slots should never trigger missing-file requests.
12. Run `npm run build`, `python3 scripts/pack-preview.py work/Dadinkowa-Preview.html`, then open that HTML as a local file. Repeat Skip, Scroll to discover, Atelier from Contact, all routes, filters, modal and WhatsApp draft checks in HashRouter mode. URL should remain a valid `#/...` route after section navigation.
13. Capture Home/Lookbook/Contact screenshots at all three widths and, if supported, a short recording showing hero advance/pause, reveals, filters and modal exit. Screenshots alone do not validate transitions. Record browser/version, dimensions and observed issues. No screenshots or recording were captured in this session.
